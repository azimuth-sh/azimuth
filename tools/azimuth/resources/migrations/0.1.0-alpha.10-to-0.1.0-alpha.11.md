# Migration: 0.1.0-alpha.10 to 0.1.0-alpha.11

Migration line: alpha-requirement-scenario
Account transformation: none

Alpha.11 keeps the alpha.10 account grammar, so authored accounts need no edit. Run `azimuth update` to align the installation with this release; it refreshes the `azimuth-implement-change` skill and the verification reference.

Changes:
- Unit inputs are read from the working tree that source capture sees: tracked plus untracked non-ignored files, with files deleted from the working tree omitted. A tracked deletion no longer aborts `run snapshot`, and a new untracked source file now changes its unit's input fingerprint, so hermetic-unit reuse cannot carry a result across an unrecorded source change.
- The `azimuth-implement-change` skill names the run pipeline (`run snapshot`, `run affected`, `run select`, `run plan`, `run execute`/`run import`, `run verify`) as the way relied-on Checks execute, and the verification reference states the same sequence.
- A source file linked into several compilation units no longer fails export, qualification or `project observe` as duplicate sites: records identical in every field, including the source fingerprint, collapse to one together with their identical marker companions, while records that share an identity but differ in any field still fail.
- `run plan` and `run select` accept `--repository` for catalog-backed loads with supplied manifests, with the same rules as `export` and `run snapshot`.
