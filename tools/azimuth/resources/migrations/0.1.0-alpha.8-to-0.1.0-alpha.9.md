# Migration: 0.1.0-alpha.8 to 0.1.0-alpha.9

Migration line: alpha-requirement-scenario
Account transformation: none

Alpha.9 keeps the alpha.8 account grammar, so authored accounts need no edit. Run `azimuth update` to replace the skills and the intent-delta and outcome references.

Changes:
- An intent delta that removes a Requirement or Scenario still referenced by realization, verification, support, workspace obligations or code `Realizes` sites no longer stops `change validate`, `change intent-preview` or `change status`. The references are owed by the change's later realization and verification deltas and implementation.
- `change validate` reports each still-referenced removal as a `removed-identity-referenced` error. It names every referencing location and the facet that owes the repair, and it counts the change's own realization and verification deltas, so it clears once they remove the references. Dangling-declaration findings at the same locations are not repeated.
- `change intent-preview` writes the preview unchanged and lists the owed repairs on standard error. A preview captured while repairs were owed is still the reviewed target when it is applied.
- `change intent-apply` and `archive` still refuse a removal that the accepted account or linkage references. Their error now lists the referencing locations.
- `change finalize` applies a change's pending facets itself. It accepts `--preview <intent-preview>` and `--account-preview <account-preview>`, refuses a stale or missing preview for a pending facet, composes the pending intent and account deltas onto a staged copy of the accepted model, and refuses a removed identity only if the composed account still references it. Every finalization gate runs on the composition; on any refusal nothing is written. A Scenario rename whose verification delta binds the successor, which neither `intent-apply` nor `account-apply` could apply first, now finalizes in one step. A change whose facets are already applied finalizes exactly as before and takes neither option.
- `migrate plan` chains consecutive release edges, so an installation several releases behind (for example alpha.6) is planned through every intermediate migration instead of being reported as unsupported.

A change whose `change validate` aborted with "has current realization or verification references" now validates. Treat the new `removed-identity-referenced` findings as the repairs the later deltas owe.
