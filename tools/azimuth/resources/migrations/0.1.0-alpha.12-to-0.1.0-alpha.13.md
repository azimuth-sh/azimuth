# Migration: 0.1.0-alpha.12 to 0.1.0-alpha.13

Migration line: alpha-requirement-scenario
Account transformation: re-extract source linkage

Alpha.13 keeps the alpha.12 account grammar, so authored accounts need no edit and authored Requirement, Scenario, Check and Mechanism IDs do not change. Run `azimuth update` to align the installation with this release. TypeScript/JavaScript Mechanism sites can change identity, so re-extract the affected TypeScript populations with the matching alpha.13 emitter and regenerate qualified and observed manifests, worksets, companions, bindings, fingerprints and launch plans from the new manifests. Python and .NET sites are unchanged. Reassess reviews only where a blocking source definition changed under the existing drift rules. Historical manifests, reviews and Run facts keep their original identities; do not rewrite them.

Changes:
- A TypeScript/JavaScript Mechanism marker belongs to its first function-like ancestor. A returned named function expression uses its own qualified name, canonical signature and source fingerprint (for example `dispatch.handleRequest(string):string`) instead of the enclosing factory's.
- Named function expressions keep their own names after containing binding segments (`bound.handleRequest`, `handlers.bound.handleRequest`). Directly identifier-bound anonymous functions and arrows use their variable, object-property or class-field binding; class fields carry their declared instance or static receiver. Nested object properties participate in qualification.
- Markers in getters, setters, constructors, class static blocks, unbound anonymous functions or arrows (including callbacks passed as arguments), and unnamed or computed enclosing scopes now fail extraction with a file-and-line diagnostic. They were previously attributed to an outer callable; move such a marker into a named callable.
- `contracts/verification.md` defines the complete form table.
