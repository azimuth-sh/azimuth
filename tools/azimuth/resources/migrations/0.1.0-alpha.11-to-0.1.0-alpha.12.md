# Migration: 0.1.0-alpha.11 to 0.1.0-alpha.12

Migration line: alpha-requirement-scenario
Account transformation: re-extract source linkage

Alpha.12 keeps the alpha.11 account grammar, so authored accounts need no edit and authored Requirement, Scenario, Check and Mechanism IDs do not change. Run `azimuth update` to align the installation with this release. Source identities emitted by the Python and TypeScript extractors change, so re-extract affected source populations with the matching alpha.12 emitters; old Python manifests and affected TypeScript manifests are not reusable. Regenerate qualified and observed manifests, worksets, companions, bindings, fingerprints and launch plans from the new manifests. Reassess reviews only where a blocking source definition changed under the existing drift rules. Historical manifests, reviews and Run facts keep their original identities; do not rewrite them.

Changes:
- Python `realizes` and Check-implementation sites change from bare qualnames to `<module>.<__qualname__>`, matching Python Mechanism and probe identities. Same-named functions in different modules of one Area no longer resolve to one native address. Core uses the complete site as the native address without adding another prefix.
- TypeScript/JavaScript Mechanism signatures qualify retained local named types by declaring module and type name (for example `./src/state::State`) instead of refusing them.
- External named interfaces and exported compiler-named aliases carry their declaring package, module and name with no version or installation prefix (for example `@types/mdx::./types::MDXComponents`); resolved `@types/*` names are retained. External aliases keep their own names and canonical generic arguments rather than expanding dependency bodies. Local alias expansion is unchanged, and source aliases the checker erases still use their canonical target types.
- Named default-exported callables use their declared names; anonymous default exports remain invalid.
- Template-literal signature unions canonicalize every member without leaking a `|` into the site.
- Conflicting semantic identities, missing package or module accounts, non-exported external aliases, unresolved declarations, import-type nodes and type queries remain extraction failures.
- Release publication waits up to 60 seconds for npm dist-tag reads to reflect a just-acknowledged tag change before refusing the release channel.
