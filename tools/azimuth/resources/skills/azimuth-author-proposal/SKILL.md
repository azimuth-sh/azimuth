# Author a proposal

Read the repository instructions, original request, captured handoff, accepted account and `azimuth reference show proposal`. Resolve singular change authority and relevant exploration decisions. If material scope or product behavior remains undecided, identify the decision instead of hiding it in implementation instructions.

State the present problem, observable outcome, included and excluded work, affected stable Requirement identities, assumptions and inspectable completion conditions. A change should be implementable and acceptable as one coherent transition. For a correction, identify the original change, exact failed basis and findings without rewriting the archived record.

Keep the proposal at `Status: proposed` during authoring. Declare unchanged intent only through the installed explicit declaration and reason, never alongside intent delta files. Do not embed complete facet deltas or execution reports merely to duplicate their owning artifacts.

Check that each completion condition has an observable result and that exclusions do not contradict the requested outcome. Record unresolved operational prerequisites honestly. Proposal review permits further authoring; it does not itself authorize implementation.

Run applicable structural validation and inspect the actual artifact. Retain the proposal and exact input references required by the handoff, then return its compact result. Do not author the independent review, advance shared workflow state unless assigned, or commit implicitly.
