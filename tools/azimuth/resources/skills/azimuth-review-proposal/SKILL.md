# Review a proposal

Load `azimuth reference show authoring-reviews` for the exact result, stable issue and correction-disposition contracts.

Read the original request, repository instructions, captured handoff, proposal and its declared dependencies directly. Use `azimuth reference show proposal` and `azimuth reference show workflow` for format and result contracts. Be distinct from the author; a coordinator's summary is navigation rather than the review basis.

Assess whether the proposal faithfully addresses the request, defines one coherent transition, locates singular authority, includes all participating repositories, and makes scope, exclusions, assumptions and completion conditions explicit. Check that an implementer will not have to invent product behavior later. Identify unjustified expansion or exclusions that make the promised outcome impossible.

Review any originating exploration decisions and any correction relationship to prior changes. Require explicit decisions for material uncertainty; do not resolve it by rewriting the proposal yourself.

Complete the assigned assessment after finding the first blocker so the author receives the full set of material issues. Give each review issue a stable identity using the installed contract, exact basis/location, violated proposition, consequence and bounded correction. These authored issues are not deterministic model Findings.

Retain an accepted/rejected result with positive acceptance reasoning or actionable rejection issues. Reassessment references its predecessor and explains every prior disposition. Preserve adverse history; changed relevant inputs require a fresh assessment. Return the result without editing the proposal or manufacturing implementation permission.
