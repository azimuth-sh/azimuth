# Challenge planning conformance

This self-contained synthetic experiment exercises repository decision use and semantic Challenge planning through public `azimuth` commands. It owns a standard Requirement with a current Qualification and Requirement Judgment, one requirement-specific analyzer enrolled as a Check, mutation and broad-analysis Verification Challenges, a distinct fault-injection Verification Challenge and capability, all seven selector forms, an exact workspace, one linkage manifest and a short-lived standard-library adapter.

The gate proves that a surviving mutant is a `findings` Challenge Result, a fully killed mutant set is `clean`, and zero generated mutants or skipped tests are `inconclusive`. A fault activity may be shared by one Check attempt and one Qualification Challenge attempt, while their Check Result and Challenge Result remain distinct records. Mutation, analyzer and fault modes emit only their own native outcome codes. The requirement-specific analyzer produces a Check Result; the broad analyzer produces a Requirement Judgment Challenge Result.

The gate also checks each exact selector relation, target and fingerprint, route-local scope and accountable launch input, broad composition, required-form, candidate-cap, Qualification-context and cross-form failures. An isolated authored selector proves that zero resolution is a planning error distinct from a zero-mutant result. Scheduled omission retains gate work, import provenance echoes the exact staged id, digest and size, and selection drift preserves caller-owned output. It invokes `validate`, `export`, `adapter verify`, `run plan`, `run execute`, `run import`, `run verify` and `run inspect` only.

This is conformance evidence, not a provider service. The adapter is a fresh bounded process for each exchange. The experiment creates no ledger, ingest command, assurance state, daemon, cache or durable provider state; a clean Challenge Result is not product evidence and does not qualify a Requirement.

Run the gate from any directory:

```sh
experiments/challenge-planning/check.sh
```
