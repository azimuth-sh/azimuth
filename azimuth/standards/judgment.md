# Judgment standard

## Assurance challenges

Policy: targeted

An imported challenge is optional judgment context for changed or high-risk non-routine claims. It
does not create a `Covers` relation and never upgrades evidence strength. The exact report, tool
version, configuration inputs and resolved realization, evidence or mechanism subjects enter each
bound claim's judgment fingerprint. A changed observation or subject makes the prior judgment
stale.

Ordinary `azimuth check` validates imported structure but does not execute external tools. A project
or change chooses which challenges to run and when to refresh them. A broad scan has no implicit
claim scope: its adapter derives explicit bindings from existing linkage, and no-finding output is
not product evidence.

### Mutation testing

Mutation testing challenges whether selected evidence distinguishes generated changes at linked
realization sites. For an assessed claim, the judge SHALL inspect survived, no-coverage, timeout,
runtime-error and pending mutants against the claim predicate. A relevant surviving mutant makes
the covering evidence `toothless` until the evidence or claim is corrected. Killed mutants support
that review but do not by themselves make a judgment `sound`.

There is no project-wide mutation-score threshold. Scope is declared by the mutation tool's
repository-owned configuration.

### Static analysis

Static analysis challenges claims only where the analyzed artifact resolves to their realization
sites. The judge SHALL inspect relevant adverse findings and an adapter-declared inconclusive run.
A clean broad scan supports the review rationale but does not establish any product predicate.
