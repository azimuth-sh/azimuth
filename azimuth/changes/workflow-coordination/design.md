# Workflow coordination design

The core is a deterministic, dependency-aware coordinator boundary. Reusable declarative templates own action identities, bounded outcomes, required input bindings, output contracts, guidance and current-success dependencies. The shipped change-development template expands explicit module and later validated assurance inventories into stable action/typed-target identities. Runtime instances pin the template revision/fingerprint, concrete definitions and actual result histories; checkout locations remain in a separately supplied local repository map. They do not execute agents or infer approval from artifact presence.

The harness resolves local paths, obtains service-authenticated snapshots, launches independent reviewers and supplies results. Read-only queries give complete eligible handoffs without recommending execution order, with no `next`, `blocked`, `current` or `superseded` fields. The same reference identifies definition dependencies, corrections, results and reviews. Published handoffs flatten prerequisite artifact references into inputs; prerequisite result envelopes and author identities remain internal to eligibility and independence validation. Eligibility and currentness are assessed internally. Internal graph keys encode that tuple losslessly rather than hash its target. Content fingerprints remain separate drift detectors. Conditional updates validate current input basis and supporting records and publish one atomic state transition. Independent proposal review gates module authoring and receives the request, scope and proposal records. Negative authoring reviews route to author correction followed by independent reassessment. Assurance rejections route to configured implementation or execution correction; another registered candidate appends an assurance generation while preserving superseded tasks and all earlier results. Existing assurance review validators and assessments remain the source of qualification, applicability and Judgment semantics.

ASS registers candidate authority projections under the existing project's fingerprint identity. Candidate registration and accepted selection are distinct operations. Exact revision snapshots contain bounded, consistent authority, linked reviews and latest Run corrections; no projection creates a positive review.

Operational workflow state should live outside examined source captures until the consumer capture explicitly excludes it. No automatic source ignore or archive/runtime relocation is claimed in this increment. Local actor labels are harness assertions; service ingestion supplies credential-backed review identity.
