# Workflow coordination design

The core is a deterministic, dependency-aware coordinator boundary. Configured finite task definitions declare inputs, output contracts, guidance and dependencies. Runtime instances record actual result histories, explicitly supplied roots and exact definition identity. They do not execute agents or infer approval from artifact presence.

The harness resolves local paths, obtains service-authenticated snapshots, launches independent reviewers and supplies results. Read-only queries give complete eligible handoffs and a recommendation. Conditional updates validate current input basis and supporting records and publish one atomic state transition. Negative reviews route to author correction followed by independent reassessment. Existing assurance review validators and assessments remain the source of qualification, applicability and Judgment semantics.

ASS registers candidate authority projections under the existing project's fingerprint identity. Candidate registration and accepted selection are distinct operations. Exact revision snapshots contain bounded, consistent authority, linked reviews and latest Run corrections; no projection creates a positive review.

Operational workflow state should live outside examined source captures until the consumer capture explicitly excludes it. No automatic source ignore or archive/runtime relocation is claimed in this increment. Local actor labels are harness assertions; service ingestion supplies credential-backed review identity.
