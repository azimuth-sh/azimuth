# Design: Project validation and coordinated verification Runs

## Account validation

Use the catalog as topology authority and the complete workset as revision-pinned input selection. Derive mounts and qualified source identities inside core. Stage prospective intent and account deltas before resolving producer descriptors, so candidate package entities are not rejected merely because they are absent from accepted intent. Preserve exact accepted files and immutable historical records.

One change validate entry point combines prospective structural inspection. Reports separate errors in account structure, incomplete evidence and acceptance obligations. No-declared-blockers is not an independent assurance conclusion.

## Run execution

Keep one exact Subject and one global semantic Plan. Partition routes by explicitly configured adapter, perform isolated bounded exchanges and retain verified child bundles in the coordinated Run. Global fingerprints and verification cover adapter identities, route partition and child content. Single-adapter exchange remains usable alone; different Subjects cannot join. Corrections retain immediate predecessor identity and child provenance.

Declare minimal execution requirements on compact Checks. Resolve a small family-routing policy into exact selected Checks and Cases. Derive whole units by default and retain explicit finite partitions. Report missing eligibility and routing rather than using hidden broad fallback or optimistic completeness.

## Review preparation and state

Generate exact review inputs from authored definitions, selected current authority, independent records and active Run heads. Do not create opinions, decisions or reviewer metadata. Review freshness follows relevant method, Case, binding, mechanism, Claim and observation dependencies rather than global model drift. Propagate stale applicability into dependent Claim assessment even if the previous conclusion was unresolved.
