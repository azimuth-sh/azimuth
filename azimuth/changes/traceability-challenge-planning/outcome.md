# Outcome: traceability-challenge-planning

Status: implemented

## Result

Azimuth now authors strict total-composition Claim Judgments and resolves all seven Challenge Plan
selector forms to an explicit account of selected and adverse candidates. Decision Policies name
required open forms, and the one current Challenge Schedule assigns every required or declared form
to a `gate | scheduled` lane without making schedule part of decision identity.

The complete-model planner accepts Check-only, Challenge-only and mixed requests. Requested
Challenge Plans name one explicit configured capability, finite work units and a nonzero candidate
cap. Planning requires exact current decisions, context, form coverage and one adapter, then emits
stable target-derived Challenge selections with canonical semantic scope. Launch routes repeat the
projectable scope as accountable inputs with exact locators; relocation preserves semantic target
and scope identity while changing launch identity.

Marker-derived mechanism implementations now use ecosystem-semantic qualified sites, path-free
typed bindings and exactly paired companion Artifacts across all seven public emitters. Raw and
assembled manifests reject prior or mismatched shapes rather than interpreting them through a
compatibility path.

The mutation, fault-injection and broad-analysis experiment exercises the public planning,
execution and import commands. It keeps Check Observations distinct from Qualification and Claim
Judgment Challenge Results, distinguishes clean, findings and inconclusive results, and proves
scheduled omission and selection drift without inventing execution facts.

## Departures

- Mechanism identity required a stricter correction than the initial proposal described. The
  existing two-argument source annotation remains, but each raw implementation record now carries
  seven exact fields and an exactly paired Artifact. Assembly rewrites both identities atomically,
  and explicit design bindings cannot reuse marker-only Artifact identities.
- Relocation review separated semantic and accountable identity precisely. File location is absent
  from mechanism, decision and Challenge-scope fingerprints, but remains in source locators, model
  accounting and launch fingerprints.
- Candidate caps count every unique record reached by each requested Plan before cross-Plan target
  deduplication, including adverse candidates. Overlap can merge an exact target only when its
  Challenger, form, lane, scope, units and route remain compatible.
- Required-form coverage uses the fixed union of requested Plans. Core does not automatically add
  a capability, Challenger, Plan, selector, path, glob or whole-suite fallback.
- Conformance review split fault injection into its own Challenger, form and capability and made
  the shared physical activity produce one direct Check Observation plus one distinct
  Qualification Challenge Result. Runtime outcomes are derived from the selected form, exact route
  inputs and form-specific native semantics rather than copied request labels.
- Fixture migration extended beyond the initially identified transport fixtures. Strict D48
  grammar and launch inputs also required current CLI and federation fixtures plus one existing
  JavaScript TypeScript project configuration; no compatibility reader was added.
- Integration review found a parallel test race in a timestamp-only temporary directory name. The
  helper now adds process and atomic sequence identity and has direct collision regression coverage.
- Public and agent guidance was updated only after the executable boundary stabilized. It records
  current planning and preserves the distinction between a returned timed-out Run fact and a host
  deadline that prevents a valid response.

## Residual decisions

- Durable Run ingest, authorization, correction acceptance, retention, revocation and Assurance
  State remain the Run-ledger change. Local protocol validity and clean Challenge Results create no
  credibility or current-state conclusion.
- `model.extract` remains a declared capability class without a current Run operation. Extractors
  remain public short-lived tools outside Challenge execution and import.
- The framework does not define provider-native selectors, automatic capability choice, changed-file
  inference, budgets, cache validity, cadence or cross-Subject reuse. Production provider adapters
  and package publication remain separate changes.
- Adapters remain bounded short-lived processes. Daemons, webhook hosting, event gateways, hostile
  workload isolation and non-escapable descendant containment are not current capabilities.
- Every canonical Claim remains routine during the fast-moving alpha. A later accepted change must
  raise criticality and author the resulting non-routine decisions deliberately.

## Acceptance boundary

- The canonical root gate is not yet an acceptance fact in this environment. Its Rust phase passes,
  but unprivileged MSBuild cannot bind its local named-pipe server and fails with
  `System.Net.Sockets.SocketException (13): Permission denied`. The exact root command must be rerun
  in an execution environment that permits that local build primitive.
- The final implementation includes modified and untracked files while both local `HEAD` and the
  remote branch remain at `9cd0a39`. This package neither has Git write authority nor permission to
  commit or push, so the tracked release-isolation account cannot yet include the new experiments.
- A hosted workflow receipt can cover only the exact committed and pushed revision. It cannot attest
  to the current working tree, and no such receipt exists yet.
- After the coordinator commits and pushes the complete content, release isolation, the canonical
  root gate, composed validation/export/traceability and the hosted workflow must pass against that
  exact revision. Until then, proposal acceptance, finalization and archive would manufacture an
  execution account, so `finalization.json` is intentionally absent.
