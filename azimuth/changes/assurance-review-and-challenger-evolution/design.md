# Design: assurance-review-and-challenger-evolution

## Claim assessment and execution

### Definition assessment

`assurance_review.rs` projects complete Claim dependencies into a review-input packet. Its definition fingerprint includes the Claim, Cases, authored design and verification, semantic realization sites, selected mechanisms, Check implementations and independent package inputs, plus selected Challenger declarations and configuration. `review_authoring.rs` compiles aggregated Markdown into strict native `claim-review` records. The packet identifies accountable source inputs without assigning an execution Subject to the review.

The reviewer supplies an accepted or rejected assessment, rationale, authored dependencies and optional agent/model provenance. The compiler validates structure and exact inputs; it does not supply reviewer acceptance. A predecessor reference identifies a retained earlier assessment of the same target. Correction produces another record and preserves the earlier record.

### Observed health

Check execution binds a Run to an exact source, artifact or deployment Subject. `claim-health` records pin current Claim Review and exact active Observation basis. Core resolves that basis against supplied immutable Runs and their correction heads. A supported conclusion requires all declared Case contributions to be satisfied and current; violated requires an observed violation. Missing, stale and inconclusive facts remain unresolved. Source identity alone does not authorize health transfer to a built artifact or deployment.

### Objection searches and reassessment

Machine Challenger declarations are part of verification. Tagged implementations and pinned scope configuration define provider-native work; Claim and Mechanism realization tags select semantic production scope. The adapter records concrete inclusion reasons, exclusions, unresolved mappings and tool-induced expansion while keeping build dependencies separate from mutation targets.

A Challenge Result identifies the assessment fingerprint it challenges and its own execution Subject. Review packets include scoped retained objection facts and native artifact references, even when execution used a mutated Subject. Reassessment pins the inspected objection basis. Adverse results against the exact current assessment prevent unqualified acceptance or support; clean results are negative search facts.

### Local correction and shared assurance

The workflow maintains local mutable coordination state separately from immutable review and Run records. Independent reviewers can operate locally through exact handoff packets. CI publication validates a selected snapshot and preserves native records; it does not impersonate a reviewer. ASS persists and exposes selected authority, retained assessments and executions for team inspection. Neither local draft history nor the existence of a published record automatically selects accepted authority.

## Historical design explanation

The existing Residue explanation describes the credibility problem that separate Method Qualification records attempted to address. The current solution retains that problem but assesses Check credibility and each declared Case contribution together in Claim Review. Authored method labels and honest realization markers remain independently reviewable claims rather than proof.

Inline Evidence Bindings identify a Check-to-Case pair and describe its contribution. They do not require separate decision IDs, Decision Policies, Method Qualification or Applicability Decision records. Review dependencies include all selected contributions and source implementations, so altering a helper, oracle input or contribution can invalidate the definition assessment.

Claim Health composes actual Observations for an exact Subject using a current accepted definition review. It reports missing and inconclusive contributions rather than importing results from a different Subject or treating review acceptance as product satisfaction. Historical declaration parsing remains available for inspection and does not migrate approvals.
